# Independent combined Trim host production review

## Conclusion

No concrete correctness or admission bypass found in the reviewed production
draft against corrected core v2 (`3a3324a92ffb72aab82db13fe01bb19ebf18a17471fc344c8e90d947371558f7`).
This is read-only source review, not runtime qualification. No Cargo, native,
media/browser execution, checkout changes, commits or worktrees were performed.
Root is still extending the independent host tests.

## Admission and mutation boundaries

- `preview_source_trim_edit` reads one command snapshot under one SQLite
  transaction. Existing `read_command_snapshot` checks project, expected head
  revision and distinct new revision before resolution. Nonzero previews use
  `prepare_current_command_with_admission`, the same core/receipt path used by
  ordinary preview and commit. No descriptive JSON supplies command authority.
- A is always admitted, including zero intent. Used eligible B is admitted when
  Roll is nonzero or the resolution has an overwrite footprint, even when the
  final B tail is absent. B's receipt therefore cannot escape validation merely
  because the reducer retires it. Zero, pure Slip and non-Roll Ripple do not
  acquire a B receipt requirement. Missing/ineligible captured B at R=0 remains
  the core's explicit unavailable neighbor, not a newly invented Source target.
- Every admitted physical owner checks the entry asset/qualification identity,
  canonical stored receipt-derived AssetRecord, retained Original binding,
  immutable asset contract in the next document, exact current Source, and full
  measured video/audio spans in both resolved before/after Sources. Existing
  core admission checks affine A/V coherence and selected-window/offset math.
  Absent Source audio remains intentionally absent; it is not reconstructed
  merely because the asset has a measured audio stream.
- Retained physical Sources must equal the resolved Source exactly. A retired B
  must have no physical Source in the candidate. Its asset record remains the
  same durable contract. An unretained hypothetical B mapping does not introduce
  new media or a new asset into the result.
- Zero preview still requires an unused revision and exact empty resource roles
  through `result_identities`; wrapper/Split/filler/timing values cannot hide in
  this path. It requires `next == current`, exact duration and A's media
  admission, then returns `edit: None`. Raw zero authoring still reaches the
  core refusal and never creates history. Nonzero timing freshness and pool
  freshness/collisions remain core-owned, with allocation-to-new-revision also
  checked by the host.
- The common store preparation path invokes the new validator before write
  planning. The unsupported-platform refusal list includes `ApplySourceTrim`.
  Existing immutable revision/history/cursor/redo writes occur only after all
  admission succeeds in the surrounding transaction.

## Accepted refinement of the host plan

The written host plan originally requested redundant checks of final direct
child identities, final A/B crop/output ranges and the entire retired B subtree.
The reviewed validator checks physical Sources and total output duration but
does not duplicate those structural checks. I raised this difference; root
explicitly refined the plan to keep host-specific receipt/Original/full-span
and metadata admission here, with core tree validity/pruning owning wrapper,
overlay and descendant retirement. This is not an unresolved defect: `next`
is exclusively generated by core `apply` inside the same private store path;
there is no caller-supplied next-document ingress into this validator.

Host tests should assert actual final structure/output and exact inverse, as
root plans. Indexed picture and decoded PCM qualification remain independent
requirements. In particular, no old numeric target slot is cached by the host
and incorrectly reused after an In-side Split.

## CLI behavior

`live_project::execute_short` has the new dry-run branch before the generic
preview branch. It returns protocol 1, `committed: false`, the exact optional
transaction and `source_trim_edit` resolution. Ordinary edits still call
`store.commit` and report one resulting revision. Standalone command dispatch
and authenticated owned-project operations both use this same function; there
is no alternate combined-command fallback with weaker receipt checks. A failed
owned connection is not replayed locally. The zero dry-run response preserves
`edit: null` through serialization.
