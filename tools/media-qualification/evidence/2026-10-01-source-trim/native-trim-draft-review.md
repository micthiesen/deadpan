# Native Trim draft review

## Recommendation

Retain every accepted adjustment when Tab changes the active mode. Treat In, Out, Slip and Roll as controls in one unsaved Trim session, not as separate commands. Tab changes which part of the draft `h/l` adjusts; it must not reset another mode's intent. `r` changes the draft's Ripple/Overwrite policy where that policy applies and triggers a fresh full resolution.

Use a Trim-specific typed intent and one command for the complete result. Do not commit one `TrimSource` or `SlipSource` per nudge, and do not add a generic command batch/macro path. The current core command request applies one semantic command to one base snapshot (`command.rs:610-679`); source Trim's `RootSoundEditCapture` and audio reanchor happen around that whole command (`sound_routing.rs:471-485`). A list of store commits would produce multiple history entries and intermediate revisions. An unbounded operation log would store gesture history instead of compact current intent and would make the reducer replay intermediate clamps.

A bounded shape is:

- `TrimCapture`: immutable session/project/base revision, Sequence scope and parent, selected direct child and output range, entry cursors/pane/view/Visual selection, plus the adjacent child identities/ranges needed for Roll. Store `Option<Result<Capture, Error>>` so absence or ineligibility at entry cannot be repaired by a later selection.
- `TrimIntent`: active mode, Ripple/Overwrite policy, and separate accepted In, Out, Slip and Roll positions/deltas in the captured coordinate system. Preserve each operation's kind even when different intent combinations produce the same visible Source geometry; their timing and root-sound semantics can differ. Store only this bounded typed state, not an event log. Re-evaluating the same complete intent against the immutable capture must be deterministic, but gesture order is not necessarily irrelevant because earlier accepted adjustments can change later clamps.
- For a nudge, resolve the candidate against the full currently accepted intent. Only the resolver's applied value becomes the next accepted per-mode position/delta. Keep requested-versus-applied amounts for explanation, but discard clamped excess before the next nudge. This makes a reverse nudge after reaching a handle move away immediately instead of consuming hidden overshoot. If preparation is pending, coalesce input into the typed candidate state and admit only the latest proposal; never advance accepted state from a stale reply.
- `TrimProposal`: complete typed intent plus an ID containing session, project, base revision, draft and monotonically increasing change. It also retains one exact revision-bound command request. A mode change increments `change` too, because the selected join/pair changes even when media geometry does not.
- One core/store command (evolve `TrimSource` or add a narrowly named `TrimSourceEdit`) carries the complete typed intent. Core/store must define how to validate and allocate the timing identities needed for all affected owners under that one revision. Core resolves all affected targets from the captured base and returns one forward/inverse edit. The store rechecks the captured source receipt(s) when preparing and committing that command. Preview yields one proposed snapshot; Enter writes one new revision/history entry. The combined timing, binding, root-sound and mark calculation remains unresolved below.

The resolver should define how independent In/Out endpoints combine with Slip and Roll before UI implementation. Keep each nudge as an integer project-frame move of the active exact endpoint/offset, while retaining fractional endpoint gaps. Clamp against the full accepted intent, not a stale per-mode proposal. Ripple/Overwrite behavior must derive from the complete before/after allocations, and Roll must name and validate both sides of its join. **The combined final timing, root-sound, binding and mark algebra is still required design and implementation work; this note does not solve it.** If a full resolver is not ready, implement only a clearly labelled In/Out preview subset and leave the complete `,v`/Trim mode unclaimed; do not make Tab discard accepted edits.

## Native service and preview contract

Reuse the Slip invariants in `project/slip.rs`, `project/service/slip.rs`, and `preview/slip.rs`, with Trim-specific typed fields rather than broadening Slip's `delta_frames`:

1. Capture the target and any Roll neighbor at Trim entry. Keep the selected child/wrapper and occurrence explicit. No later cursor, selection, workspace refresh or async reply may supply a replacement. A changed session/revision/scope invalidates the whole draft and requires reopen.
2. Every edit, policy toggle and mode change immediately revokes old preparation/presentation tickets and stops any draft audition. Submit one replaceable proposal against the immutable base. Accept only the latest proposal ID and a proposed snapshot derived from that same base.
3. Before/Proposed pictures are keyed by full snapshot identity, boundary side, exact Edit frame and viewer raster. Apply/Enter is enabled only after every available outgoing/incoming picture for the active proposed join has decoded and been GPU-submitted at the current raster. At a document edge show an explicit edge label; do not fabricate black or decode a nonexistent neighbor. A stale or half-rendered pair cannot authorize Apply. Preserve the previous accepted pair on preparation/resize/decode failure and keep Apply disabled.
4. Enter consumes the service-retained request for the exact ready proposal once. Success creates one receipt before workspace refresh. Consume that receipt only for the matching applying draft; a refresh failure reports that the edit was saved and requests reopen, without retrying. Cancel restores the captured cursors, pane, scope and selection only if the captured base is still current. A stale draft must not restore stale context.
5. The store validates every source whose media map changes, including both members of a Roll, against the stored receipt and asset contract. UI proposal data is never media authority. Reopen/Undo/Redo use the single durable transaction.

## Timing, sound and marks

- Keep project frames, source frame/PTS positions and 48 kHz samples distinct. Derive output sample edges with `B(frame)` from the applicable before/proposed revision; never add rounded per-nudge durations. Ripple moves suffix content; comparison windows must map the same semantic edit site in each immutable snapshot rather than assume equal absolute frames or durations.
- The implementation must determine how to compute timing/reanchors and root-sound changes for the combined accepted intent from the captured base. Do not transform root sounds once per active tab or each gesture. Roll must capture both incident owners before changing either map. Preserve exact phase/resume and raw sampling support, and derive editorial fade markers from the final changed joins. This algebra is unresolved and must be settled before wiring the UI.
- Label any waveform's clock and coverage. `preview/gain/waveform.rs` supplies owner-definition data with bounded/unknown coverage, not a full mixed Edit waveform; do not relabel it as one. For context audition, use immutable before/proposed snapshots and absolute sample windows, preserve independent root sounds in the full edit mix, and revoke/stop output whenever the proposal changes.
- Transform marks once from the original document to the final document, with the established exact boundary and source-PTS rules. Intermediate preview states must not persist marks or attachments.

## Keyboard and focus

- Route Tab/Shift-Tab to mode cycling only while the Trim workspace/heading owns focus. If a native text field or IME composition owns input, preserve its normal Tab/Enter/Escape behavior; do not route h/l or `r` there. If text entry is not needed, avoid adding a field solely to carry an amount that the spec assigns to frame nudges.
- In the Trim background, `h/l` adjusts the active mode by one project frame and Shift gives ten. `r` toggles Ripple/Overwrite only for modes where the policy applies. Enter applies only the current ready Proposed state and does not repeat; Escape cancels after composition handling. Keep the active mode, focused pane and current preview status visible.
- Capture and preserve real Original/Edit cursors, focused pane and Visual selection at entry. If Visual selection makes the selected-beat target ambiguous, reject entry with a clear message instead of silently consuming or clearing it.
- Add `,v` and any `:trim` alias to the production Kestrel compatibility matrix, including text focus, IME, non-US layout, key repeat, focus changes and captured absence.

## Existing boundaries

The design notes correctly identify reusable parts: Slip's target/proposal/receipt lifecycle; `worker/endpoints.rs` and `preview/splice/pictures.rs` for bounded paired pictures after adding committed/proposed content identity; and `preview/splice/comparison.rs` for absolute before/proposed sample-boundary mapping. The current store/core path has no generic batch command. Keep the new atomic request specific to Trim and wait for stable Roll/Overwrite, target-neighbor and sound-transform semantics before wiring the native mode cycle.
