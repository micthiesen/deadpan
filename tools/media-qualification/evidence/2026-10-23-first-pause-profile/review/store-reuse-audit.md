# Store/core reuse audit for first-pause follow-up

Read-only audit of `command_plan`, inverse checking, validation proofs, and history receipts. No measurements or implementation claims added.

## Existing checks and reusable mechanisms

- `crates/deadpan-store/src/lib.rs:1398-1437` serializes the typed request, applies `check_document_size`, decodes the exact JSON through the bounded replay reader and checks typed equality. It does the same for `EditTransaction`, then checks `edit.inverse.restores(&next, &current)`. This admits typed callers under the same wire limits as reopened history, verifies exact inverse restoration, and guarantees the stored request/edit decode to computed semantics. Keep all these checks and the stored JSON bytes.
- `crates/deadpan-store/src/lib.rs:1566` deserializes `plan.request_json` a second time, after `command_plan` already decoded and equality-checked those bytes. This is a small, structurally safe reuse opportunity: retain the already decoded, replay-admitted `CommandRequest` in `CommandPlan` and pass that exact decoded value to `write_command_plan`; continue storing and using the same JSON for history and let later replay parse it normally. This removes only the immediate second parse. It does not remove the typed-to-wire roundtrip, ingress byte/depth/value limits, or on-open replay. The measured phase totals do not establish whether this parse is significant.
- `DocumentPatch::restores` at `crates/deadpan-core/src/command.rs:919` already performs conflict/bounds checks and compares every resulting field via `patched_equals` without materializing a restored document; the audio binding patch has its own `restores` method. That is the exact inverse check and is already the no-copy affordance. Replacing it with a value shortcut would weaken the invariant.
- `crates/deadpan-core/src/command.rs:1873-1945` builds the forward patch and calls `result.validate_after_with(previous, forward.audio_bindings, known_structure)` when a retained head proof is available. `crates/deadpan-core/src/document.rs:1131-1160` reuses unchanged owners' binding proofs and known structural durations; changed owners are validated. `apply_validated` at command.rs:1071 also starts from the retained validated head. The resulting `ValidatedDocument` goes directly into `CommandPlan` and the store cache after commit. These are the existing validation-reuse paths; no second full production result validation is needed in `command_plan`.
- `command_plan`'s forward-patch application equality and complete-validation comparison are `#[cfg(debug_assertions)]` only. They are valuable development assertions but are not production runtime cost in the release benchmark.
- `crates/deadpan-store/src/generation_preparations.rs:431-445` has `verify_for_writer`: a current receipt with matching revision count/head/dependencies avoids full history verification, then validates the generation-preparation store. `crates/deadpan-store/src/lib.rs:1638` extends the receipt for the new revision after its replay checks. Preserve this receipt trust path and its fallback when dependencies mismatch; do not replay less on its authority.
- `crates/deadpan-store/src/lib.rs:866-904` makes one immediate SQLite transaction, calls prepare/write, commits, then inserts the validated head into the in-memory cache. `transaction.commit()` remains the durability boundary. Keep it intact.
- `docs/TIMING_STORAGE.md:312-335` documents compact `patch_wire`: exact child splice reconstruction and omission of an inverse only when it equals `forward.inverse()`. Decoding still reconstructs the same typed edit. This already limits history JSON size for large root sequences without changing inverse semantics.

## Safe direction and limits

The only concrete redundant operation found here is the post-roundtrip second decode of the same `request_json` at `lib.rs:1566`; the already decoded request can be carried from `command_plan` as the write-plan input while retaining its equality check and stored bytes. Treat the expected savings as unmeasured and likely bounded; it cannot explain away a large phase without finer timings. The observed inverse-restoration, edit roundtrip, serialization bounds, full transition admission, receipts, transaction commit, and retained validation proof have distinct integrity roles. No evidence here supports removing, merging, or weakening them.
