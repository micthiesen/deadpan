# Minimal DP-24 first-pause profiling experiment

Instrument a disposable archive copy only, then run the existing `perf edit` workload for one pause cycle against a fresh 10,000-Hold package: `perf make-large <fresh-package> --beats 10000`, then `perf edit <fresh-package> --cycles 1 --kinds pause`. The edit command creates a random root boundary and times command construction, store commit, then workspace refresh separately. Preserve stdout/stderr, stage load, source tree identity and hashes of the executed `perf` and `deadpan-cli` binaries. One cycle targets the first-bind path but gives no distribution; compare with separately retained measurements if needed.

The script `overlay.py` copies an unpacked archive to a new destination (ignoring `.git` and `target`) and applies exact-match instrumentation. Invoke `python3 overlay.py --source <unpacked-archive> --dest <new-temp-dir>`. It refuses the shared checkout as source and refuses an existing destination. Every anchor must occur exactly once or patching stops; use a fresh destination for every attempt. I dry-applied all replacements to a scratch fixture containing the four exact current source files and a Cargo.toml marker, then inspected the generated Rust around each timer. The apply_validated wrapper preserves its Some(document) call and the original mapping to ValidatedDocument. I did not compile it. The shared checkout was not modified.

Timers use `std::time::Instant` and `eprintln!`; they do not change authored values, branch conditions, validation calls, or results.

- `crates/deadpan-core/src/insert_time.rs::apply_known` times the ordinary root-Sequence reducer and splits out `capture_for_insertion_scoped`, the loop over shifted physical siblings (including owner count), `validate_bindings_in_scope`, and `insert_leaf_shared`. Its whole reducer duration exposes work outside those blocks. The 10k root-Hold fixture should take the normal root-boundary path. The earlier interior split path has early returns and no reducer total; treat missing phase lines as an invalid/alternate-path run, not zero cost.
- `crates/deadpan-core/src/command.rs::apply_validated` times the full core call. A second timer around `net_transaction_known` reports patch diff, final result validation, and reversible transaction construction. The core-total minus reducer/net phases represents intervening command setup, transforms, pruning, and compaction; do not sum nested durations.
- `crates/deadpan-store/src/lib.rs::ProjectStore::commit_inner` times `prepare_command`, `write_command_plan`, and `transaction.commit()` separately. Prepare includes current snapshot/read, core apply/net validation, transition/admission checks, and command/history payload preparation. Write plan includes reconciliation, revision/history/state writes, and receipt extension. The history edit and inverse already exist from core net construction; this does not isolate inverse serialization from the rest of preparation.
- `crates/deadpan-cli/examples/perf/edit.rs::measure` emits explicit commit-plus-refresh and refresh times. Existing JSON reports prepare/commit/refresh/total arrays. Refresh reads the validated head, compiles the `RenderPlan`, and clones the workspace document.

The SQLite transaction commit timer includes its durability sync. Timers add small unmeasured overhead, and stderr adds extra work. The owner-loop timer groups per-owner resolution and resume-term construction. The explicit binding-validation timer isolates one call only. Store prepare and write remain grouped. perf refresh is not the full interactive native service. A single cycle gives no p95. Pair phase timings with a 1 ms sample profile of the isolated commit if necessary, retaining command, binary hashes and load. Do not infer dominance by subtracting nested phases when paths or errors differ.

Expected successful run prints reducer total, capture, owner-loop (with 10k count), new-binding validation, leaf, core net, store prepare/write/transaction commit, and perf refresh lines, with no refusal.
