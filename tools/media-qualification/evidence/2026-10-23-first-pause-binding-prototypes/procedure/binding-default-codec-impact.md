# Binding-default codec impact audit

## Conclusion

The six proposed defaults alter the current wire representation of `AudioBindingState` and the nested `AudioBindingPatch` stored in command history. Core schema 58 and SQLite package schema 87 cover the current project envelope and stored package respectively, but neither provides an independent version header for standalone `AudioBindingState` JSON. The old schema fixture validators also have their own closed field grammar. Preserve their explicit historical wire shapes rather than relying on the new current-type serializer.

Before the new defaults can work on the current standalone/nested codec, update `AudioBindingState::from_json`'s independent borrowed preflight: its `Template` helper at `crates/deadpan-core/src/audio_binding.rs:2069-2076` requires both `arguments` and `births` as `&RawValue`, and `preflight_binding` reads them unconditionally at 2078-2082. Serde defaults on `AudioPlacementTemplate` do not affect this earlier preflight. These should become absent-or-present bounded raw fields, treating absence as zero entries while preserving the existing `bounded_json_sequence` limits and validation for fields that are present.

## Affected current codecs

- **Versioned authored document:** `ProjectDocument` stores `AudioBindingState` at `crates/deadpan-core/src/document.rs:597-627, 663-667`; current document schema is 57 at `document.rs:13` and exact-schema validation occurs at 1282. Under the proposed Core58, the new encoded representation is covered by that document gate. Document serialization uses the current `AudioBindingState` implementation.
- **Versioned SQLite history:** `DocumentPatch.audio_bindings` carries `AudioBindingPatch` at `crates/deadpan-core/src/command.rs:761-765`. `AudioBindingPatch` derives Serialize and custom-deserializes guarded timing, binding and gap-binding changes at `crates/deadpan-core/src/audio_binding_patch.rs:32-43, 315-345`; its typed binding values are `OwnedAudioBinding`. `EditTransaction` and its compact patch wire nest `DocumentPatch` (`crates/deadpan-core/src/command/patch_wire.rs:200-218`). Store planning serializes, decodes, equality-checks and inverse-restores the edit at `crates/deadpan-store/src/lib.rs:1415-1427`; history replay recalculates and decodes the saved transaction at `crates/deadpan-store/src/validation.rs:612-631`. SQLite87 is the package boundary for this on-disk history-format change; keep Core58 and Store87 refusal/version tests aligned.
- **Standalone, unversioned audio-binding JSON:** `AudioBindingState::to_json/from_json` are at `audio_binding.rs:1823-1890, 1983-2035`. The state wire has `timings`, `bindings`, and optional `gap_bindings` / `sound_clocks`, but no schema/version field. `AudioBindingState::from_json` performs its own bounded raw preflight before typed decoding. Core58 does not tag this standalone API input or output. Either explicitly accept that the standalone JSON vocabulary changes without a header under the project's no-old-package-compatibility authorization, or introduce a separate envelope/version if this API is expected to negotiate formats independently. At minimum preserve duplicate, depth, entry and byte checks; do not treat Serde defaults as a substitute.

Under the six proposed attrs, the typed codec behavior is: `AudioClockRoot::ProjectRootRoundEven` omitted/restored by `AudioReferenceClock`; empty `arguments` and `births` omitted/restored by `AudioPlacementTemplate`; zero `AudioLocalPhase.constant` and `AudioResume.local_boundary` omitted/restored; and absent `OwnedAudioBinding.resume` omitted/restored as `None`. The proposed `root`, `arguments`, `births`, `constant` and `local_boundary` defaults are actual semantic values, not permission to drop nondefault contexts, paths, phase, or boundaries. Keep existing strict `deny_unknown_fields`, custom bounded decoders, and unknown enum/tag rejection.

## Historical and adjacent codecs

- **Core schema 20/21 legacy validators:** `legacy_audio_binding_v20.rs` and the test-only old field definitions in `legacy_audio_binding_v21.rs` explicitly require `root`, `arguments`, `births`, `local_boundary`, and `constant` (`legacy_audio_binding_v21.rs:143-238`); their reader checks are used by the test-only v20/v21 wrapper (`legacy_audio_binding_v21.rs:73-103`, `legacy_audio_binding_v20.rs:43-56`). Their `LegacyAudioBindingState` projections serialize the current `AudioBindingState` transparently. Once current serialization omits defaults, these projected “old” snapshots no longer preserve the v20/v21 explicit wire format and the v20/v21 decoder's own round-trip/rejection fixtures can fail. Keep explicit historical fixture bytes or a legacy serializer for those tests; do not silently weaken the strict old-header grammar as collateral.
- **Core schema 22:** `legacy_audio_binding_v22.rs:36-55` validates old frozen layouts, then parses bindings through current `AudioBindingState`; its old state validator treats the bindings payload as `IgnoredAny` (`legacy_audio_binding_v21.rs:111-121`). So unlike v20/v21 it does not itself require these five fields. Its projection still serializes current state, so tests that intend to preserve a schema-22 byte fixture should pin or explicitly construct the old wire form.
- **Core schema 35/36 fixtures:** `legacy_audio_binding_v35.rs:31-40` routes test-only legacy binding decode through the current bounded `AudioBindingState::from_json` and schema-36 validation; `legacy_audio_binding_v36.rs` is test-only (`lib.rs:57-59`) and checks introduction of `reference_local_offset`, reanchor anchor, and frozen editorial fields. These are not alternate production current binding codecs, but their test projections wrap/serialize the current state. Verify they still represent their intended historical schemas after omission; no need to change their frozen-layout reader for binding fields.
- **FrozenAudioContext schemas 1–12:** `audio_context.rs:19, 109-137, 151-158, 229-255, 314-328` has its own context schema, but capture explicitly rejects authored sounds and nonempty `audio_bindings` before freezing (`audio_context.rs:151-158`); it serializes `FrozenAudioLayout` with explicit edges. Its versions 1–12 therefore do not contain the six binding fields. The only adjacent legacy check is frozen-layout validation, not binding-template validation.
- **Sound clocks:** `SoundClockJournal` and `SoundClockReference` are a separate serialization (`sound_clock.rs:262-285, 382-388`) using timing/scope/owner IDs and repeat/group/split data. `AudioBindingState` embeds them in optional `sound_clocks`, but sound-clock records do not nest `AudioReferenceClock`, `AudioPlacementTemplate`, `AudioResume` or `AudioLocalPhase`; no independent sound-clock wire version needs changing for these six attrs.
- **Frozen layout:** timing records inside `AudioBindingState` do contain `FrozenAudioLayout`, but that is a different codec and these attrs do not touch its nodes/edge vocabulary. FrozenAudioContext's explicit-edge serializer is likewise unaffected.

## Required focused proofs

1. Current standalone and document round trips for each omitted default, both omitted and explicit form; assert exact decoded type equality. Include every nested location for placements: lattice, resume phase term, and reanchor placement.
2. Nondefault-value retention for all six: non-root clock scopes, each nonempty path, nonzero boundary and phase, and `Some(resume)`. Ensure omitted defaults do not normalize any nondefault input.
3. Preflight parity: missing empty path fields are accepted as zero work, while present duplicate/oversized paths still fail the same limits; test paths nested inside all three placement locations. Test absent resume as zero work and malformed present resume/phase terms remain rejected.
4. Full `EditTransaction` serialization/decode, `AudioBindingPatch` apply/inverse exact restoration, and package history replay under Core58/SQLite87. The stored edit has no separate payload schema field, so verify the package gate refuses the old package before attempting history interpretation.
5. Keep historical v20/v21 strict fixtures explicit and prove their version-specific validators still reject newly introduced vocabulary. Pin v22/v35/36 fixtures to intended historic wire where that matters. Do not retrofit the new current omission behavior into FrozenAudioContext or SoundClock formats.
