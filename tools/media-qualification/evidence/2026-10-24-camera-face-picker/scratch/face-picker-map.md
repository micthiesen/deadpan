# Detected-face proposals in Camera’s numbered picker

Read-only map; no repo changes or builds/tests/runtime runs. §7.6 is normative (docs/spec/DEADPAN_SPEC.md:450-460): the picker contains detected regions, saved targets, center and corners; digit selection is explicit; f refreshes; r resets; Enter commits one framing edit and Escape restores entry state.

## Recommended minimal design / traps

1. Add a face-proposal payload to PickerTarget (for example, owned DetectedFace plus picture identity), not a persisted AttentionTarget. Store admitted proposals in Camera/picker state scoped to (session, revision, asset, indexed PTS) and a detection ticket. f starts/refreshes DetectFaces; it should leave the current draft and saved targets untouched while pending. On completion require matching ticket, camera session/revision and exact currently displayed Original picture, then pass the same captured-context/cursor/scope guard used by face zoom. Clear stale proposals on picture or revision change. Unavailable/failed/no-face returns a visible reason and leaves picker usable.
2. Preserve saved-target digit priority and existing center/corner entries. Add proposals in a documented stable order (host already validates left-to-right/top-to-bottom); only entries with number Some(1..=9) are selectable. There can be up to MAX_FACES proposals, but the current UI has a one-digit budget: do not invent multi-digit input or silently renumber saved targets. Render proposal state/confidence distinctly from saved (“drawn”) state, and show pending/error state accessibly.
3. On a digit for a face proposal, create its fresh ID/label and face_target, submit only Operation::Save, and wait for the exact save receipt before rebasing Camera. Do not save the proposal set, siblings, or framing. Retain adjusted scale/curve/draft and keep Camera open; target save gets one Undo. Then user can explicitly select/follow the newly saved target and Enter commits the separate framing edit (second Undo). Escape before Enter restores entry presentation. Safest literal “save target only” semantics keep pose unchanged and require explicit follow/selection after it becomes saved.
4. Handle a selection race: while face detection/save is outstanding, disable/reject other digit selections and f refresh or bind them to a generation; stale save completion must never rebase a different Camera/picture. Existing save rebase only covers an own target save, so also check the original picture ticket/identity when admitting the result. Escape/session replacement cancels pending presentation state and must not let late detection reopen/alter Camera.
5. Decisive replay: delayed scripted faces; f shows pending but no revision change; completion paints ordered numbered proposals; selecting face 2 creates only its SetTarget, preserves draft and Camera, leaves face 1 absent; one Undo removes target while draft remains; redo restores it; explicitly follow then Enter creates exactly one framing revision and a second Undo removes only framing; stale picture/cursor/revision completion, failed/empty proposals, clipped projection and >9 entries do not mutate or select wrong target.
