# Publication provenance source review

Disposition: no actionable findings in the frozen provenance implementation or its tests.

## Scope

Reviewed `crates/deadpan-cli/src/encoded_render/publication/provenance.rs` and `provenance/tests.rs` against specification §22.7. Followed only the dependent APIs needed to establish historical receipt binding, generated picture interpretation, privacy, and bounds. Filesystem publication was excluded. No repository changes, builds, tests, formatters, native programs, or commits were run.

## Evidence

- Historical identity: `capture` receives an opaque `VerifiedCandidate`; `capture_revision` reads `snapshot_at(contract.revision_id())`, checks project and revision IDs, and compares the entire committed document SHA-256 with the captured candidate. It does not use the live document or history cursor. `ProjectStore::snapshot_at` explicitly resolves immutable historical and abandoned revisions without recovery.
- Source evidence: `catalog` is explicitly labeled `committed_catalog_superset`. Qualified entries carry the immutable receipt ID, algorithm-tagged original object reference and measured SHA-256. `registered_source(revision, asset)` reconstructs and compares the historical asset record with its receipt. Receipt reads independently check canonical evidence, receipt identity and the original ownership record's byte length and SHA-256. The alias cache removes only display labels and otherwise requires complete asset-record equality. Unqualified entries do not promote arbitrary authored `content_hash` strings into verified evidence.
- Effective generated use: the scan calls the production `RenderPlan::picture` resolver for each selected output frame and retains only `Picture::Accepted { generated: Some(..) }`. It therefore uses the resolved Repeat play, effective gap override and Retime mapping. Dormant branches do not become intervals. Adjacent spans coalesce only when the complete artifact agrees, including provenance and sampling. Blank seams remain separated. Artifact references contain sampled/native master identities and immutable provenance; the latter binds retained conditioning transitively as explicitly documented.
- Privacy: the serialized catalog contains no asset labels, paths, URLs, linked-source bookmarks or arbitrary unqualified hash strings. `OriginalObjectRef` contains only content identity and byte length. `GeneratedArtifact` contains asset IDs, three immutable object references and the sampling map, with no prompt or source labels. Core IDs have a bounded alphanumeric/underscore/hyphen grammar. The encoded manifest and verification result are the already captured engineering evidence, without authored labels.
- Bounds and control: output scanning is capped at one million frames, catalog and generated artifact tables at 4,096 entries each, and generated intervals at 65,536. The picture plan retains compact Repeat indexing. Interval arithmetic stays within the validated nonnegative half-open range and uses checked endpoint construction. Each frame and catalog item checks cancellation/deadline; snapshot, receipt and compilation calls are checked before or after their synchronous boundaries. The final serialization counter fails above 16 MiB and preserves explicit cancellation/deadline outcomes. These controls are cooperative and do not preempt a store read or plan compilation already in progress.
- API integrity: provenance fields are private and serialize-only. Public capture cannot accept a deserialized provenance report or an unverified movie. The report honestly records `explicit_engineering_choice`; it does not claim automatic platform selection has been qualified.

## Tests reviewed

The five source tests exercise sparse play and effective gap overrides under Retime, dormant-gap exclusion, artifact/interval limits, full-artifact equality, blank seams, compact huge Repeat admission limits, historical capture after a live edit, label and unqualified-hash omission, document-hash rejection, cancellation/deadline classification, and the 16 MiB serialization cap. These tests were reviewed, not executed by this reviewer. Parent-owned actual-source and generated encoded qualification remains the intended integration evidence.
