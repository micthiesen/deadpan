# Sparse play overrides and schema-4 verification

This report covers `Edit individual Repeat plays with sparse owned subtrees`,
based on `cc2494c043e450a49e7da443c38e817fb1a7770c`. It implements a prerequisite
for editing a partial repeated selection without flattening the Repeat or
changing every play. DP-04 and Gate B remain partial.

This is the original override checkpoint. Subsequent automatic isolation through
complete occurrence paths is recorded in [nested occurrence verification](OCCURRENCE_VERIFICATION.md).

## Implemented behavior

A schema-4 document stores sparse overrides by authored Repeat node and stable
iteration identity. Each entry owns an ordinary subtree using the existing five
primitives. The default child remains editable and supplies non-overridden plays.
An override may have a different duration. Nested override subtrees remain
structural, and every node still has exactly one owner.

`set_play_override` installs or replaces a selected play's subtree;
`clear_play_override` removes it and restores that play's default. These commands
share the normal reducer, revision checks, dry-run, forward/inverse patches, and
durable undo/redo. Whole-subtree replacement requires fresh node IDs. Existing
override nodes can be edited with the ordinary commands. Imported subtrees
normalize both nested Repeat allocations and override keys. `changed_ids`
includes an affected override owner even when its primitive node is unchanged.

Reordering and inserting plays retain surviving overrides by identity. Shrinking
removes retired override subtrees in the same transaction; undo retains their
exact meaning. Growth allocates fresh plays and cannot inherit retired overrides.
Removing an enclosing subtree also removes all its nested overrides.

[`RepeatLayout`](../crates/deadpan-core/src/repeat_layout.rs) builds prefix segments
from compact identity runs and sparse override boundaries. Validation, boundary
queries, mark transforms, and picture plans share this mapping. Gaps remain only
between plays and belong to the preceding stable identity. Position lookup uses
binary search over segments. Identity lookup scans segments, never expanded
plays. Exact Retime composition still rounds only at the final query boundary.

Instance paths must enter the selected play's effective child. The default child
cannot be targeted through an overridden play; an override root cannot be used
with another play's identity. Marks on replaced/removed content follow their
explicit loss policy. Marks in surviving plays and gaps follow the same identity
through duration changes and reorder. Unresolved marks do not reattach when an
override is cleared or a different subtree occupies its time.

## Migration and fixture provenance

Schemas 1, 2, and 3 migrate directly to schema 4 using strict legacy adapters,
complete chronological replay, and the existing consistent-copy/atomic-promotion
path. Every old snapshot and transaction must match, including abandoned branches
and pending redo. New override maps must be empty in every upgraded legacy
projection. Schema-3 marks retain their exact coordinates, ownership, bias,
loss policy, and state. Unknown override fields or commands in an older schema
are rejected even if an injected map is empty. Backups are retained as
`Snapshots/before-schema-4-*.sqlite`.

The new [schema-3 fixture](../crates/deadpan-store/tests/fixtures/v3-history.sql)
was generated by the compiled CLI from the base revision above, before source
changes. All edits and history navigation used that CLI. SQLite `iterdump`
exported its final rows. The fixture has 23 revisions and 17 edit records,
left/right marks, occurrence retirement, both owner-loss policies, pinned marks,
Repeat resizing/insertion/reordering, an imported Repeat subtree, an abandoned
branch, and two pending mark redos.

- Old CLI SHA-256: `064399f24e6becfa38359bdc07e907953be6154e3f6efc5554f2e316b213d896`.
- SQL fixture SHA-256: `766f3440d0f1fda62fa2e232c10a2d4b03c8e75eb1555427fe0d1bc244be57a6`.

Existing schema-1/2 fixtures remain unchanged. Tests compare every legacy
snapshot and edit, preserved backups, repeat identities, exact marks, reopened
redo/undo, and current-schema idempotence. Corrupt mark histories, unexpected
vocabulary, and faulty override projections are rejected. Existing disk-full,
process-crash, oversized-row, and live-WAL-reader checks remain in the suite.

## Verification

On 2026-09-20, the complete repository gate passed on Apple M5 Max, 128 GiB RAM,
macOS 26.5.2 (25F84), with Rust 1.97.1 and locked dependencies. Formatting,
workspace Clippy with warnings denied, workspace tests/build, and `deadpan-cli
doctor` all passed. There were **143 passing Rust tests**, none ignored: 74 core,
34 store, 21 plan, 12 CLI, and two native headless tests. All six Python audio
measurement regressions also passed. Diagnostics reports document schema 4 and
keeps media, interactive keyboard editing, AI, export, and distribution marked
unimplemented.

The [eight new core tests](../crates/deadpan-core/tests/play_overrides.rs) include
an expanded-reference property test for durations and biased boundaries, variable
play offsets, valid/invalid occurrence branches, mark loss, nested identity
normalization, wrapping override roots, replacement/clear/delete, retired plays,
invalid ownership graphs, overflow atomicity, empty overrides, and high ordinal
boundaries. Every successful test edit checks exact inverse restoration and
serialization round-trip.

The [five new picture-plan tests](../crates/deadpan-plan/tests/play_overrides.rs)
compare actual plan requests with original source coordinates, including nested
Retimes, gaps, immutable prior plans, inverse restoration, reordered/inserted/
retired plays, and randomized independently expanded small references. A
`u32::MAX`-play fixture with one middle override uses four authored nodes, one
identity run, three duration segments, and one override; seeks use at most four
segment comparisons. This is structural lookup evidence, not decoded playback
or a product latency benchmark.

Store integration tests exercise preview isolation, commits, reopen, undo/redo,
clear, retirement, and stale targets. The CLI process test exercises the same
commands with an open writer, reports duration changes, inspects the effective
picture occurrence, rejects stale requests, and restores an override through
undo. No window or media worker is initialized for this verification.

Two independent reviews found no actionable issues. The core/plan review covered
variable durations and gaps, exact Retime mapping, compact lookup, effective
occurrence paths, ownership and ingress bounds, imported identity normalization,
nested cleanup, mark loss, and inverse atomicity. The separate persistence review
covered all three legacy adapters, complete migration replay, preserved marks and
identities, and rejection of new override vocabulary in old schemas, including
empty injected maps. The core reviewer also reran the targeted override and
picture-plan tests successfully.

## Remaining work

The commands address an authored Repeat and one stable play, including inside an
already installed override subtree. Automatically isolating a complete nested
occurrence selection is still required: editing an authored inner Repeat directly
currently affects every outer occurrence using that node. Partial range splitting
and wrapping, role-only overlays, temporal attachments, copy/paste/explode,
incremental plan rebuilding, and audio mapping remain open.

No source decoding, device audio, GPU preview, inference, or export is added by
this change. The native UI remains the welcome shell. GUI aesthetics, native
focus/IME, accessibility, and natural keyboard navigation still require actual
editor implementation and focused interactive review. There were no GUI changes
to justify live computer use for this slice.
