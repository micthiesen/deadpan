# Current-chunk permission population, 2026-10-27

The Components path now predicts complete current-chunk contribution permissions
before contribution PCM allocation. It compares those predictions with an
independent carrier populated by successful numerical reads, including untouched
negative samples. Original Root/Domain queries are prepared once and consumed
by the actual read. This implements current input policy population; recursive
resource admission and batching remain open.

## Production boundary

Prepared direct, current occurrence and routed sound queries expose their real
final suppression/exhaustion policy through borrowed visitors. Their translation
and classification helpers are shared with numerical readers. Routed output
does not inherit a child's exhaustion vector; direct signal policy does not
invent suppression from arbitrary leaf silence. Half-open typed ranges validate
before explicit-mask emissions or PCM zeroing. Current selection, active Original
support and positive sound-gate predicates are shared without changing their
lazy evaluation order.

The Original request is sealed to the exact plan/context pointer, sample range
and fade mode. It keeps the old query construction/charge order and transfers
the same request to the real reader. No provider or pretend PCM supplies
metadata. Unselected contribution rows are already provably all-false: population skips
those sound policy walks and prepares Original metadata only when the exact
selected/alias predicate admits Original. Actual media reads remain. The
inherited main cache adapter validates prepared requests before lookup;
misses consume them, while hits incur the real extra metadata work and preserve
fresh dependency admission. That existing cache and its two new tests stay in
uncommitted WIP. The independently published runtime has no such cache.

A supported Components chunk reserves both permission payloads alongside normal
PCM/program residency. It allocates flags and populates predictions before
contribution PCM. Numerical producers update only actual observations after
their finite checks. Every packed word must agree before finish; false positives,
false negatives and missing producer coverage fail explicitly. A successful
comparison drops the predicted payload and subtracts only its actual capacity
from both active residency and the chunk reservation. Inline header accounting
remains. Failed/partial work is neither refunded nor reused.

Context::Retained and actual Projected sound inputs retain explicit scalar
fallback before extra prediction allocation or Original preparation. Complete
final policy does not exempt Stage, Bound or projected descendants from future
native resource admission. Prediction comparison occurs after input reads and
before common owner temporal callbacks through mix.finish. Event-return input
preparation can already have allocated native state. This is a consistency
oracle, not a recursive cold-allocation proof.
