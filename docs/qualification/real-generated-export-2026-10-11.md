# Real Generated Hold export, 2026-10-11

Real accepted LTX pictures pass full preview-versus-export comparison at
1080p60 and 4K30: **225 pictures, six complete audio windows, zero measured
audio offset and no content, container or timing failures**. The emitted 4K
movie fails comparison against its pre-acceptance Freeze on all 15 Generated
frames, so the check distinguishes accepted footage from the fallback.
DP-16 and DP-17 remain partial.

## Fixtures and procedure

Two new two-second Originals use `testsrc2`, H.264 with B frames, explicit
limited BT.709 tags and stereo AAC. Their audio is the existing large-recipe
chirp: a 100 ms sweep from 300 to 1500 Hz every half second, starting at 0.2 s,
with left gain 0.7 and right gain -0.6. Silent intervals separate the chirps.

Normal `project create-original` imports each source. The shared semantic
`macro apply` path executes `InsertPause` at one second with a 500 ms length,
capturing the real Freeze provider and framing. Real local generation with
seeds 813 and 814 produces separate qualified Ready candidates, each with 17
native 768×320 pictures at 24 fps. Explicit `accept-hold` commits them. Neither
generation nor acceptance uses the synthetic worker.

Public `render` exports each complete committed revision through the ordinary
qualification, encoding, emitted-file verification and publication workflow.
`verify-export --every 1` then compares every picture and all automatic audio
windows with the committed canonical picture/audio paths. Before/after document
dumps are identical. The independently calculated reference provenance is
checked for every output frame: before the Hold, Original frame `n`; inside,
Generated frame `n - start`; afterward, Original frame `n - length`.

The reference Mac is the M5 Max / 128 GiB / macOS 26.5.2 machine, using Rust
1.97.1 and qualified FFmpeg 8.0.3 decoder/encoder libraries. Source fixtures
are generated by the separately pinned development FFmpeg executable. The
copied release CLI and helpers are those from the
[app playback qualification](generated-app-playback-2026-10-11.md); their
production source is unchanged by that harness-only implementation.

## Retained failures and limits

The preceding long 4K playback fixture also exports successfully, and all 19
selected pictures pass, including every Generated picture. Its steady 440 Hz
tone cannot establish absolute audio alignment: the content verifier correctly
rejects 19 of 21 windows as `audio_offset_unobservable`, with no nonzero offset
observed. That run is not counted as successful full A/V comparison. The new
chirp fixtures resolve this evidence gap without relaxing thresholds.

The first chirp source omitted usable transfer/primary declarations in its
H.264 bitstream despite generator color arguments. Import correctly refused
`SourceVideoDecodeFailed` / `unsupported_transfer`. The corrected source uses
the explicit `h264_metadata` filter to tag the known BT.709 test pattern.
The original rejected source and logs are retained. The initial driver also
needed to parse Render's documented JSON event stream instead of one JSON
object; the completed movie was reused after correcting the driver.

All 446 adjacent-picture comparisons in the two final runs are unobservable
at the existing lossy-code error bound. Picture fidelity, exact PTS order and
the hand-derived reference provenance pass; this does not recover a source
frame identity from nearly identical decoded pictures. The verifier shares
the picture/audio implementation with export, as documented in
[preview/export verification](../PREVIEW_EXPORT_VERIFICATION.md).
Nested Generated operations, broader format/effects coverage, physical display
appearance and listening are separate obligations. No native window or other
agent was used. No product code changed in this qualification.
