The [closed grammar](../SOURCE_ADMISSION.md) follows the
[AV1 ISO binding v1.3.0](https://aomediacodec.github.io/av1-isobmff/v1.3.0.html)
and the pinned decoder source. The Main sequence header is parsed before
decoder initialization or packet submission. This matters because libdav1d
uses a private allocator: ordinary FFmpeg allocation callbacks cannot enforce
its bounds. All possible size-override dimensions fit the configured dimension
ceiling, while dav1d's `frame_size_limit` checks the actual pixel product before
allocation. Packet work, layers, frame count, interpretation and metadata are
bounded independently. The first guarded packet can supply an omitted config
sequence. Copied packet provenance distinguishes a displayed coded key from a
show-existing reference to a hidden key.

FFmpeg's libdav1d adapter parses only sequence information from extradata.
Deadpan explicitly retains static av1C metadata as stream side data, so it
cannot disappear when absent from the first packet. AV1's chromaticity and
luminance units differ from HEVC; exact conversion uses the common metadata
contract, with invalid/unrepresentable declarations recorded as ignored.
Extreme unsigned luminance outside FFmpeg's signed rational range is refused.
Conflicting or changing declarations fail before acceptance.

## Fixtures and measurements

`generate_av1_fixtures.py` authors 128x96 Main pictures using development-only
FFmpeg 9.0.1/SVT-AV1 4.2.0. The retained fixtures exercise both depths and ranges,
3:2 SAR, left/top-left chroma, missing VFR picture positions, multiple GOPs,
actual synthesized grain, super-resolution, PQ/HLG, config-only and packet HDR
metadata, and absent config sequence OBUs. Ordinary MP4 fixtures retain the
existing pinned mono AAC through sample 19219; the packet-metadata MP4 and WebM
fixtures are video-only. Planar decoder references are retained separately. Their full RGB
conversion is checked by independent scalar math; authored patches additionally
check decoding. The lossy multi-GOP encoder's measured neutral-patch red error
peaks at 1099.89 of 65535 codes because of a small chroma bias.

One-, eight- and sixteen-thread reads and reverse seeks preserve exact pixels,
PTS, durations and key identities. Malformed cases cover configuration bits,
large size envelopes, contradictory raster/depth/color, OBU bounds and counts,
unsupported metadata/layers, missing sequence, later corruption and poisoned
sessions. Existing container and isolated native mutation suites automatically
include the small MP4/WebM fixtures.

The first VFR WebM remux declared its average 40040000 ns duration, rather than
the authored 30000/1001 grid. That file is retained as
`vfr-with-average-default-duration.webm` in scratch. The generator now explicitly
signals the authored rate. It also exposed a host cadence gap: quantized VFR
intervals 33/34/67 ms fell through to an unusable 1 ms GCD. The new bounded
`DeclaredQuantizedVfr` evidence requires a declared standard rate, every absolute
PTS and terminal point within one tick, repeated single-unit intervals and gaps
no larger than eight units. It never changes PTS, adds frames or supplies a
missing terminal duration. Unit tests reject drift and contradictory hints.

Headless AVFoundation P010 comparisons cover five current fixtures: limited
Main10, multiple GOPs, grain, PQ and HLG. All 1,327,104 ten-bit luma samples from
108 pictures match the retained software decode exactly; timestamps also match.
Chroma differs in this Apple output-conversion path, with maximum errors of
63–75 ten-bit codes. This is not a full-picture equality claim. For super-
resolution, that P010 API exposed the 85x96 coded raster instead of the final
128x96 raster; the attempt is retained without a pixel comparison. No live GUI,
physical display, listening or independent super-resolution acceptance is claimed.
