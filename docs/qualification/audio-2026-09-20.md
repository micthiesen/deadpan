# Signalsmith Stretch candidate qualification, 2026-09-20

The [canonical scheduling follow-up](audio-canonical-2026-09-20.md) implements
and measures a worker-side strategy for the failures below. This report and
its raw candidate results remain unchanged as historical evidence.

**Gate A remains open.** Real native DSP runs establish useful pitch, duration,
level, latency, and allocation evidence, but **82 of 605 declared candidate
targets fail**. Preview/export partition equivalence, local-preroll seek
equivalence, and short-clip handling require an explicit adapter design. This is
not an integrated Deadpan audio engine, device qualification, or listening test.

Evidence is reproducible with the [developer harness](../../tools/audio-qualification/README.md),
[pins](../../tools/audio-qualification/pins.json), [native probe](../../tools/audio-qualification/probe.cpp),
[normal report](../../tools/audio-qualification/report.json), and
[ASan/UBSan report](../../tools/audio-qualification/report-sanitized.json).
The reports preserve every comparison, failure, command, source/license hash,
and PCM hash. Samples are synthesized locally; no source media or private audio
is used. No sound was played or recorded.

## Fixture and measurements

The original 48 kHz float32 stereo fixture has 192,192 frames, or 4.004 seconds.
It combines 440/660 Hz channel-independent tones, opposing chirps, separate
single-sample impulses, silence spans, reversed channel levels, and a quieter
repeat at -20 dB. It deliberately contains hard edges; Deadpan's future edge
crossfades, room-tone, permitted tails, and other mix policies are not applied.

Five speeds are crossed with -7, 0, and +7 semitones, for 15 cases. Every engine
uses `presetDefault(2, 48000)`, float samples, seed 1337, and no formant
compensation. Whole-buffer `exact()` is compared with fixed 256-frame output
blocks and irregular 257/509/127/1024 output blocks. Each block's input boundary
is calculated from its origin with nearest-even rational rounding, rather than
accumulated rounded durations. A fixed-schedule reset/replay and four
nonmonotonic local-preroll seeks are tested for every case.

| Speed | Exact output frames | Input frames used by output-seek preroll | Flush output frames |
| --- | ---: | ---: | ---: |
| 0.5 | 384,384 | 4,320 | 8,640 |
| 0.75 | 256,256 | 5,040 | 6,720 |
| 1 | 192,192 | 5,760 | 5,760 |
| 1.5 | 128,128 | 7,200 | 4,800 |
| 2 | 96,096 | 8,640 | 4,320 |

The default analysis block is 5,760 samples (120 ms), with a 1,440-sample
interval (30 ms). Input latency and output latency are each 2,880 samples
(60 ms); `seekLength()` returns 7,200. Unaligned unity processing moves impulses
from frames 12,000/15,000 to 17,760/20,760, exactly 5,760 later. With
`exact()`'s output-seek/flush alignment, both peaks return to their authored
frames. These are DSP positions, not measured audio-device latency.

Normal and sanitizer runs each evaluate **605 assertions: 523 pass and 82 fail**.
Both native probes exit 0; the orchestrator exits 1 because qualification targets
failed. The sanitizer run reports no address or undefined-behavior diagnostics.
Each run retains 130 PCM files containing 14,548,907 stereo frames, including
inputs, full outputs, failed seek excerpts, and diagnostic controls. All 130 PCM
hashes match between the normal and sanitizer runs.

Other passing checks cover unity identity (normalized RMS error
`3.86437e-7`), two raw-latency and two aligned-preroll checks, complete digital
silence at +7 semitones, and a left-only input with zero right-channel leakage.
Buffer guards remain intact. Frequency, channel-level, and dynamic-ratio tests
apply to whole-buffer outputs; all saved outputs receive the finite/length/bound
checks.

Numerical quality is limited evidence. The reports also retain chirp frequency
estimates, embedded-silence RMS, and transient energy spread. The 90% transient
energy width reaches **16,924 output samples, approximately 353 ms**, even though
the peak-displacement target passes. Embedded silence has up to 0.000792 RMS
from surrounding signal tails. These diagnostics are not listening approval for
speech, music, hard cuts, formants, or large pitch changes.

## Failures and integration consequences

**Block schedule matters.** Whole-buffer versus fixed-block normalized RMS error
reaches 1.0948; fixed versus irregular reaches 1.0950. Only unity/no-pitch passes
both partition comparisons. The two continuous-tone controls are bit-identical
at unity/+7 semitones and 0.75/no pitch. These controls were added after observing
the failure, without changing its threshold or fixture.

Inspection of the [pinned process implementation](https://github.com/Signalsmith-Audio/signalsmith-stretch/blob/57b93f4e9206a089a45387eaa39bdc9f310d3308/signalsmith-stretch.h#L210)
shows that silence detection and state reset operate on the energy and length of
each supplied input block. This is a plausible explanation supported by the
continuous controls, not proof that all partition differences have one cause.
Do not use whole-file `exact()` for export while feeding arbitrary device-sized
blocks for preview. A shared worker must own a deterministic DSP call schedule;
device requests should consume its prepared output. That adapter and its end-to-end
equivalence test are still unimplemented.

**Local preroll does not restore phase history.** The four seek requests start at
source samples 124,800, 28,800, 168,000, and 76,800, each with 14,400 input samples
(300 ms) of preceding source. The next 4,800 output frames are compared against
whole-buffer playback. Only unity/no-pitch's four comparisons pass. The largest
normalized RMS error is about 1.9923. A fresh suffix render is not a cached state
restore. A future adapter needs deterministic replay from a defined earlier
state, prepared-region caching, or another measured state strategy. This report
does not claim that merely increasing preroll solves it.

**Short clips need handling outside `exact()`.** A 1,003-frame clip (20.9 ms) with
an impulse returns false and a silent output at unity. The
[pinned helper](https://github.com/Signalsmith-Audio/signalsmith-stretch/blob/57b93f4e9206a089a45387eaa39bdc9f310d3308/signalsmith-stretch.h#L468)
requires enough input for `outputSeekLength(rate)`. Deadpan must not silently
accept that output. Padding/cropping or another deterministic short-segment path
requires its own duration, onset, and preview/export tests.

**No realtime-callback qualification.** Configuration of three fresh engines
uses 102 C++ allocations totaling 2,732,208 bytes. Measured output-seek, process,
flush, `exact()`, reset, and local-seek render calls after configuration perform
no intercepted C++ allocations. All 225 phase assertions use the configured
`steady_cpp_new_calls_max` target of zero, rather than recording counts without
enforcing them. Configuration is outside that target. The counter covers
calling-thread C++ allocation operators,
including aligned forms; it excludes direct `malloc`, OS allocators, other
threads, page faults, and locks. No device callback is exercised.

The final ordinary run's whole-buffer calls total 1,337.095 ms for 15 outputs;
individual calls take 39.930 to 175.463 ms. The processing-time/output-duration
ratio ranges 0.0150 to 0.0225. Its longest fixed-block call is 1.465 ms and its
longest irregular-block call is 1.679 ms. An earlier run of the same native probe
observed a fixed-block call of **28.136 ms**, longer than 256 samples' 5.333 ms at
48 kHz. The faster rerun does not erase that observation. These are single-run
wall times on a shared workstation and include scheduling delay. They neither
isolate CPU cost nor demonstrate callback deadlines. Keep DSP preparation off
the device callback and measure queue coverage, underruns, and scheduling in the
eventual adapter.

## Verification and remaining work

Reproduction and checks actually run:

```sh
python3 -m unittest discover -s tools/audio-qualification -p 'test_*.py' -v
python3 tools/audio-qualification/run.py --output tools/audio-qualification/report.json
python3 tools/audio-qualification/run.py --sanitizers --download-cache /tmp/deadpan-audio-discovery --output tools/audio-qualification/report-sanitized.json
```

All six analyzer regression tests pass; they inject incorrect frequency,
shifted/inverted phase, swapped channel levels, bad output lengths, NaNs, and
one allocation independently into each of a case's 15 measured phase records.
The allocation test also changes the target temporarily to prove the configured
bound is used, while the recorded qualification target remains zero.
The normal run downloads and verifies both immutable archives. The sanitizer
run reuses a verified archive cache and independently compiles and executes the
same probe. Every report contains the hashes of `run.py`, `probe.cpp`,
`pins.json`, and `test_analysis.py`; final verification checks them against the
files in this checkout.

Independent review identified missing allocation assertions outside the process
loop and a hardcoded allocation threshold. Both are fixed: every measured matrix
phase uses the declared target, with injected-allocation regression coverage.
The follow-up review found no remaining issues. CI runs the six analyzer tests;
the native qualification commands remain explicit experiments that report their
82 failed targets.

This covers part of specification Sections 10.5, 16.5, and 26. Gate A remains
open for the application adapter, canonical preview/export schedule, bounded
queues, state-aware seeks, short clips, variable-rate/reverse policy, fades,
tails, room tone, gain/mix/limiter semantics, output-device CPAL and route-change
behavior, cancellation/load/underrun measurement, speech/music listening review,
and the supported machine/OS matrix. No Rust binding or app DSP is added here.
GUI testing has no useful role in this isolated DSP experiment; natural keyboard
navigation and visual review remain separate application obligations.
