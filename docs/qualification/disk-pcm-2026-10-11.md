# Private disk-backed Preserve output, 2026-10-11

The streamed-input worker still retained its complete processed output in RAM,
limiting Preserve output to 8,388,608 frames (about 175 seconds). It now writes
outputs above 1,048,576 frames into a private temporary PCM file while keeping
one continuous canonical processor. Ordinary stages and request-local projected
stages share this storage and the existing exact resampler.

## Storage and admission

`PcmWriter` writes little-endian stereo f32 through one 2,048-frame buffer.
Finite samples, expected total length, complete writes and final file length
are checked before a prepared block becomes available. Failed or cancelled
preparation drops the private file; a writer that fails during processing
cannot retry or publish partial data. Cache I/O reports `AudioCacheFailed`.

The file is unlinked at creation and remains open only through its owning
prepared block. Bounded positional reads require the exact requested samples,
reject truncation and nonfinite data, and feed the same resampling window as
the in-memory path. There is no mapped whole-output buffer or path-based cache
re-admission. Current immutable-plan identity, stage recipe and transitive
qualified source fingerprints continue to control reuse.

The controller reserves input conversion and output buffering separately from
file bytes. Its 1 GiB disk ceiling includes cached files, active reservations
and pinned request-local projected stages. The ordinary LRU can reclaim only
unpinned entries. A failed read releases its reservation; successful children
may remain cached. Source and interpretation admission still runs on cache hits.
Non-streamed Hold processors retain their existing input/output bounds.

Default Preserve admission is now 86,400,000 frames of input or output
(30 minutes each at 48 kHz), with 134,217,728 combined prepared frames across
new stages in one request. The existing 60-second maximum caller deadline
and plan-work limits still apply. The memory/file threshold is configurable;
hard RAM, disk, stage-count and work budgets remain enforced. These ceilings
are not claims that a 30-minute stage prepares interactively.

## Verification

Apple M5 Max, 18 physical cores, 128 GiB; macOS 26.5.2 (25F84), Rust 1.97.1.
Native media uses the qualified FFmpeg 8.0.3/Opus 1.6.1/dav1d 1.5.4 prefix.

- Complete locked suites: **500 audio, 1,049 core and 72 playback tests pass**,
  with none ignored.
- Private-file tests compare every f32 bit, including signed zero, across
  multiple flushes, random windows and the final partial block. They check
  that no file pathname survives and that incomplete, invalid, cancelled,
  unwritable and truncated storage cannot produce a valid PCM result.
- Decoded-WAV integration checks cache eviction, source-free disk-budget
  rejection, cancellation/retry and a nested projected stage whose child
  file remains pinned against the parent's disk reservation.
- The long test repeats 8,192 decoded WAV samples into a 5,767,168-frame input,
  then continuously stretches it to **11,534,336 output frames** (240.299 seconds).
  All output samples match the independently mapped canonical reference.
  Late first demand, sequential reads and a second cold preparation pass with
  **133,120 resident stereo-frame equivalents** (1,064,960 bytes) and
  **92,274,688 prepared-file bytes**. FFT state, source decoding and the bounded
  resampling halo are separate; this is not a whole-process RSS measurement.
- The core four-minute edit verifies undo and document round-trip. The same
  test fails on archived `afacc963ad5b1044c8be12146987919c94ad366c` at the
  former 175-second output ceiling. The archived comparison uses a separate
  Cargo target and records the executed binary hash.
- Final disk-quota eviction, workspace/all-target strict Clippy with
  `ui-harness`, formatting and diff whitespace checks pass.

The first release export test failed because automatic verification samples
long movies, while its provenance assertions expected every picture. The
final test explicitly requests `--every 1` and writes its report before the
provenance assertions. Keep the initial failure receipt with the final run.

## Real export

The release fixture repeats Original frames `[12, 42)` 120 times inside one
half-speed Preserve processor. Its 7,200 output pictures at 30000/1001 fps
last **240.24 seconds**, with **11,531,520 presented audio samples**. The public
Render path captures one committed revision and publishes H.264/AAC MP4;
`verify-export --every 1` independently decodes it against shared preview.

- **7,200 picture comparisons pass**, with minimum luma/chroma PSNR
  **56.455/53.445 dB**. Nine independently calculated Original ordinal probes
  match the reference provenance. Of 14,398 directed neighboring-picture
  comparisons, 8,640 are unobservable at the declared fidelity; repeated
  pictures do not establish distinguishable neighboring identities.
- **240 audio windows cover the complete output**, including the final partial
  second. All **120 signal windows verify zero offset**; the other 120 are
  silent, with no timing assertion on silence. There are no uncovered samples,
  audio failures or nonzero offsets. The minimum compared-block SNR is
  **14.415 dB**, and the largest block level difference is **0.180 dB**.
- The MP4 declares 2,048 samples of priming and presents the exact terminal
  sample. No sample alignment, packet dropping or AAC-block tolerance is used.
- The final release test takes **150.43 seconds**, excluding compilation. This
  includes package creation, rendering, publication and verification, so it is
  not a standalone DSP preparation benchmark.

## Scope

Review was performed by the main session without subagents. It covers descriptor
ownership and unlinking, complete-file publication, error propagation, poisoning
after partial writes, exact serialization, bounded reads, recursive RAM/disk
reservations, pin-aware eviction, request-local projections and source re-admission.

This cache is private to the preparation worker's lifetime. Background job
scheduling, progress display, persistent content-addressed artifacts and reuse
after restart remain open. The full audio graph, independently timed group
automation, EQ/filtering, arbitrary sends, oversampled shaping and mastering
also remain open. DP-09 and DP-16 remain partial. No live GUI, listening or
physical-device qualification is added here.
