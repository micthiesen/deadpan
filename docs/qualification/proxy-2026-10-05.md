# Preview proxy qualification, 2026-10-05

This record covers the [preview proxy](../PROXIES.md) tier. It follows
[seek-2026-10-05](seek-2026-10-05.md), whose run 5 left 4K long-GOP warm seek
at 211 ms p95 against the 80 ms target. These are engineering measurements
on one machine, not release qualification.

After review, the tier changed:

- Proxies moved to the per-user cache, `~/Library/Caches/Deadpan/Proxies`.
- Only Originals above 1080p get one; long keyframe spacing alone no longer
  qualifies.
- Readers open the published file in place, hashed once per file state.
- Builds gained a stall watch with a single confirmed-teardown retry, pause,
  and space, power and failure guards.
- The VUI sample aspect and the rotation matrix are now exact.
- Verification samples sixteen pictures and checks signed per-channel bias.

Run 6 measures this reviewed design. Run 3's 1080p60 measurement of the
earlier design is kept only as context.

## Failures and robustness

**VideoToolbox's encoder service stops answering under concurrent
sessions.** A later full gate failed
`every_proxy_picture_keeps_its_original_time_and_duration` with
`Stalled { stall: 60s }`. Two kinds of run reproduced it:

- running that test binary alone (1 of 37 nextest runs);
- stress runs, with a watcher sampling every proxy worker alive longer than
  15 s.

**Evidence.** Every sampled worker was blocked in
`VTCompressionSessionCompleteFrames`, in a synchronous XPC request
(`xpc_connection_send_message_with_reply_sync` → `mach_msg`) to the
VideoToolbox encoder service that never received a reply:

- 1 worker in 200 runs of the hanging test, 8 test processes concurrently;
- 17 workers in 200 full-binary runs, 8 processes × 10 threads.

The call came either from the flush in `deadpan_proxy_finish` or from
`avcodec_free_context` after a failure. The same heavy stress also produced
two other service failures:

- session creation refused (`-12900` while setting properties);
- packets outside the one-picture-per-request contract, such as
  `pts 1024 dts 512` where 512 was expected.

The hang rate did not change with the worker's QoS (utility versus
default: 8.5% and 8.8% of runs with a long-lived worker), so priority is
not the cause. Earlier, three such events had been seen as a deadline, an
`invalid_packet` and an `Invalidate` hang.

**Fix.**

- **Report before teardown.** After any failure, and after a completed
  output, the worker abandons the VideoToolbox session instead of tearing it
  down. Its classified reply is never hidden behind a hang in
  `CompleteFrames` or `Invalidate`; process exit releases the session.
- **Classify service failures.** Session-creation and send/receive failures
  are reported as `encoder_session_failed`.
- **Retry once, transiently.** `invalid_packet`, `encoder_session_failed`
  and a stall with confirmed teardown are retried once in a new process with
  fresh staging. When the retry fails too, the build ends as a machine
  condition: it is retried on a later opening and not remembered as a
  failure of that Original.
- **One session at a time.** The builder holds a per-user encoder slot (an
  exclusive `flock` on `Proxies/.encoder.lock`), so Deadpan never runs
  concurrent VideoToolbox proxy sessions across windows or processes. The
  test suite takes an equivalent lock, since nextest runs each test in its
  own process.
- **Faster heartbeat.** The worker beats every 250 ms instead of every
  second. A healthy worker therefore never looks stalled; the hang itself
  cannot beat, because the worker is blocked in the service call.
- **Test path.** The real-media tests now build through the production
  retry path with a 20 s stall period. The pause test retries only a stall
  that happens well after its pause ended.

**Result.**

- The test binary passed 12 of 12 nextest runs under load: 10 CPU burners
  plus `deadpan-encode`'s VideoToolbox tests in a loop, load average about
  14. It takes 17 s, because VideoToolbox sessions are serialized.
- One full `cargo xtask gate` passed: fmt, both Clippy runs, 4,032 workspace tests and 885 `ui-harness` tests, then doctests. The proxy suite passed inside it.

**A Darwin `waitid` defect, found while adding pause.** With
`WEXITED | WNOHANG | WNOWAIT`, Darwin reported a stopped child. Group
teardown then treated the suspended worker as exited, and reaping blocked.
Both `deadpan-process` and the conversion supervisor now count only an
exit or a fatal signal. The pause test suspends and resumes a real worker.

**Exact interpretation, found by the new fixtures.**

- VideoToolbox writes no VUI sample aspect, so a 4:3 Original produced
  pictures whose ratio contradicted the track. The worker now writes it
  through `h264_metadata`.
- The display matrix had the opposite rotation sign. The worker now writes
  the exact matrix the source adapter maps to its quarter turns.
- A 4×2 hard-edged full-range RGB fixture cannot survive 4:2:0 subsampling.
  Verification refuses it (mean 10.3, block 35.0).

The rotation, SAR 4:3 with BT.601 matrix, Display P3 with sRGB, and 4K
downscale fixtures pass with bias at most 0.68 code values.

## Not covered

- Native-window physical display, VoiceOver reading of the label, and
  page-cache-cold proxy readers.
- The app's monitor pausing on real battery, Low Power Mode or thermal
  pressure. Only the `pmset` parsing paths exist; the pause mechanism is
  tested through the flag.
- Proxy generation resumable by completed ranges (§16.4).
- Machines without a hardware H.264 encoder, and lower tiers.
- The `ui` performance replays.
