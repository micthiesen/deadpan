## Actual Metal comparison

The offscreen qualification harness ran **84 comparisons on Metal** and passed
every case. Its report SHA-256 is
`3858485e175898471edc3e77f1bdc77d1fd1333b3d6c806e701d33b97024afb2`.
It exercises source aspect/rotation, Fit/Fill, framing, nested clipping and narrow
half-open pixel support against the CPU reference. Four new solid-coverage cases
matched exactly; the other new cases differed by at most one encoded channel
code with a tolerance of two. Working-texture tolerance was 0.0005.

The final renderer subsequently raised its scope capacity from 256 to 258 to
include structural-depth boundary layers and added a boundary test. That did not
change raster arithmetic. The Metal report does not measure a 258-scope workload.
This is an offscreen SDR comparison, not physical display, HDR, performance or
encoded-export qualification. Repeated Camera draws still upload source pixels.

## Native aesthetics and keyboard review

Two development builds were reviewed through the native app, using only the
repository's synthetic 120-frame counter/color-bar source. The first build was
SHA-256 `3f8f47bcfaa87c11a72a0ab5459f8c91c01096d6b767dffb6de472507ab217c1`;
the final corrected build was
`4df29f2d65ba76d2cdcf88f4c361a38d416a224270aeae26b3d297052896036e`.
Both were unoptimized Cargo dev/test executables, not release-performance builds.

Native creation initialized the complete source in Documents/Deadpan. The review
exercised `,f`, counted zoom, source-axis pan, target picking, reset, numeric entry,
Tab/Shift-Tab, field Command-Z, invalid input, Enter, Escape, help and project
undo/redo. A 15-frame Hold at boundary 40 was given a creep. At boundary 47 its
Camera pose was 117.5%; panning preserved the whole envelope. The final build
reopened that project, applied a scale step to 123.375%, and restored it through
native undo/redo without moving boundary 47 or changing the 135-frame timeline.
Read-only document comparison confirms only the Pause framing and fresh revision
changed in that final session. Validation after app quit passed.

The visual review compared actual 2984×1858-pixel app captures with the generated
board: a dominant picture, pinned Original, separate sounds, compact beat cards,
focused inspector and visible lavender keycaps. The main viewer shows the actual
draft output. It does not draw a misleading source-crop box over cropped pixels.
The board's saved Mug region, overview thumbnail, filmstrips and curve graph remain
targets, not implemented controls.

The first native pass found ordinary playback/navigation hints in Camera, a false
Framing focus badge, duplicate numeric errors and unavailable target-picker key
hints. The final pass verified their correction: ordinary controls disappear in
Camera, field focus alone shows the Framing badge, invalid input gives one error
and disables Apply, and the picker teaches only target selection, back, reset and
cancel. Field Up changed center X from 49% to 50%. Escape restored the entry pose.
Camera adjustment and picker layouts were visually inspected; longer inspector
contents scroll. Captures were inspected in the live session, not retained as
repository screenshot artifacts.

Native `,h` on the framed Hold refused the operation with a composition-snapshot
explanation and left the document unchanged. This is an explicit implementation
limit, not completion of framed pause insertion. A first automated file-panel
attempt submitted the parent directory too quickly and was rejected; observing
the path selection before the second Return opened the intended package.

No live CJK composition, physical non-US keyboard, VoiceOver, minimum-window
resize, GPU fault injection, acoustic synchronization or performance measurement
is claimed. Headless field/IME tests establish only their deterministic states.
