# MP4 Opus qualification, 2026-10-09

Mono/stereo family-zero Opus in nonfragmented MP4 is implemented through the
existing pinned libopus decoder. This supplies a prerequisite for assembling
higher-quality YouTube streams; downloader selection and assembly still accept
only H.264 plus AAC. DP-02, DP-14 and DP-16 remain partial.

## Interpretation and fixtures

The [Opus ISO BMFF mapping](https://opus-codec.org/docs/opus_in_isobmff.html)
defines `Opus`/`dOps`, output gain, roll recovery and edit-based presentation.
The source guard admits version-zero, family-zero mono/stereo descriptions,
an exact 48 kHz clock, one sample-exact presentation edit matching pre-skip,
and an optional initial empty edit for an audio offset. It checks every
packet's framing and physical duration before FFmpeg, even in ignored tracks.
The final packet may have a shorter presented duration. Other mapping families,
fragmented MP4 and unsupported edit layouts fail explicitly.

`mp4_opus` receipts retain the admitted packet/sample counts, channels, pre-skip,
first physical sample and available sample count. Raw native PTS, duration,
skip and discard observations must agree, including whole priming packets.
No event alignment or rounded-clock tolerance is applied. The existing
Matroska path shares the packet framing parser but keeps its own clock rules.

Eleven retained fixtures are generated by
`native/deadpan-source/tests/generate_opus_mp4_fixtures.py`. Development
FFmpeg 9.0.1/libopus encodes repository PCM; every compressed audio packet
matches the earlier WebM fixture's packet. Independent PCM references check
all available samples. Cases cover CELT, SILK, hybrid, 2.5/20/60/120 ms,
mono/stereo, +2 dB header gain, five-packet pre-skip and a 6,000-sample offset.
Each presents exactly 8,197 samples, or 7,717 after the explicit longer pre-skip.
All eleven regenerate byte-for-byte, with hashes in `opus-mp4-manifest.json`.

Three fixtures combine the sound with copied H.264, AV1 and PQ VP9 pictures.
Every decoded RGBA64 picture and metadata record matches its original. This
check caught the fixture generator's FFmpeg remux omitting VP9 chroma siting;
the generator now explicitly retains the known left siting. No production
picture decoder was changed. Native malformed-header, packet, clock, edit
and limit tests reject before decoding. Media-session tests preserve exact
random reads, reject padding reads and revalidate serialized receipts.
