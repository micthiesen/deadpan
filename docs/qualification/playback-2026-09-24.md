## Canonical sound and delivery

The new playback engine compiles one immutable revision and checks qualified
source receipts against its original records. Actual decoded AAC tests exercise
canonical PCM, monitor gain, inserted silent pauses, retained sample bindings
and outer Preserve parity. The writable project remains usable beside playback.
Cache reuse requires the same session, document, receipts and original records;
new sessions cannot reuse a revoked source capability. Source PCM has a 1 GiB
aggregate disk limit reserved from measured receipt counts before decoding.

Preparation and device control have separate persistent workers and a bounded
handoff. Tests cover stop/new-seek races, stale replies, worker panic, source
liveness, exact short EOS, starvation, route changes, report loss and missing,
stalled or contradictory clocks. These use the actual queue and a headless
device, without activating hardware in ordinary tests.

The queue now reserves a separate terminal slot beyond its 32 PCM packets. This
prevents a valid full prefill from racing the consumer before EOS can be queued.
Generation-scoped revocation is allocation-free in the tested callback path and
cannot stop a newer generation. Device faults remain distinct from revocation.
The fixed 64-interval delivery clock is exercised against three retained native
traces as well as synthetic boundaries.

Independent review found that an empty terminal report within the admitted
one-sample timestamp jitter could end before the previous PCM deadline. The
terminal deadline now also covers retained content. A queue-driven regression
keeps sample 511 current through 10,666,666 ns and admits EOS or starvation at
10,666,667 ns. Repeated terminal reports cannot postpone that boundary.
