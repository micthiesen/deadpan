# FFV1 generated-master qualification, 2026-09-21

## Result and scope

The isolated FFmpeg 8.0.3 build encoded the actual 30-frame sampled model
candidate and its 25-frame native sequence as FFV1 version 3 in Matroska. A
separate decode matched every RGB8 byte and frame ordinal. The bitstream debug
record reported FFV1 `version=3` and error-correction mode `ec=1`, which is the
slice-CRC configuration. The output contained one video stream, no audio, and
retained full-range GBR, sRGB transfer, and BT.709 primaries tags.

This supports FFV1/Matroska as the current RGB8 generated-master candidate under
the storage boundary in specification section 19.2. It does not implement
staging, promotion, accepted-master ownership, media decoding in the app, proxy
generation, or export. It is not a complete Gate A, packaging, license, OS
matrix, performance, or release qualification.

The [normal evidence](../../tools/media-qualification/ffv1/results/qualification-2026-09-21.json)
and [ASan/UBSan evidence](../../tools/media-qualification/ffv1/results/qualification-2026-09-21-sanitizers.json)
contain the commands, source and binary hashes, library hashes, exact input and
output metadata, pixel-fixture hashes, and control diagnostics. Generated media,
raw pixels, and binaries remain outside Git.

## Time representation

The source fixture retains the exact source time base, PTS, and duration for
every frame. Matroska selected a 1/1000 time base. The harness verifies each
container PTS is the nearest millisecond to the exact source PTS and verifies
the positive `DefaultDuration` implied by the declared frame rate.

For 30000/1001 fps, the container PTS begins `0, 33, 67, 100, 133, 167` and
ends at 968. Decoded frame durations are 33 ticks and the stream duration tag is
1.001 seconds. For 24 fps, the PTS begins `0, 42, 83, 125, 167, 208` and ends at
1000. Decoded frame durations are 41 ticks and the stream duration tag is 1.042
seconds.

Those millisecond values round the rational source clocks. They do not encode
each exact 1001/30000-second or 1/24-second interval. A generated-master manifest
must remain authoritative for frame ordinal, native/project rational mapping,
and exact boundary duration. The container timeline is presentation metadata,
not an exact replacement for the manifest.

An initial configuration omitted the stream frame-rate fields before writing
the Matroska header. Pixel comparison still passed, but decoded durations were
zero or incomplete. The
[retained baseline](../../tools/media-qualification/ffv1/results/zero-duration-baseline-2026-09-21.json)
records the frozen source hash, PTS, duration arrays, and controls. Setting the
validated average and real frame rate before `avformat_write_header` produced
the positive durations above.

## Negative controls and limitation

Normal and sanitizer runs each applied seven rejecting controls to all three
cases. Half-file truncation produced a missing-frame failure. Overwriting a
middle payload region produced a slice-CRC, bitstream, or RGB mismatch.
Changing one expected RGB byte produced a pixel mismatch. A zero raw header,
oversized dimension, zero frame count, and trailing raw byte were rejected
before media comparison. Every rejecting control exited 1 with a diagnostic.

Removing only the last Matroska byte remained decodable in all three cases. The
decoder logged `Truncating packet` but returned every expected pixel and frame.
This is a measured decoder limitation, not a successful integrity check. The
host must verify the staged artifact's declared byte length and SHA-256 before
decode and again at the accepted-master boundary. Pixel decoding alone cannot
prove whole-file byte integrity.

The C adapter bounds dimensions, frame count, per-frame bytes, and aggregate raw
bytes. The Python harness bounds subprocess duration. The adapter uses
exploding decoder errors, fixed RGB8
formats, single-threaded codec contexts for unambiguous version/CRC logging, and
checked scaling calls. The Python contract parser rejects extra output lines,
duplicate fields, non-finite values, booleans in integer fields, wrong exact
source clocks, non-nearest container PTS, and missing DefaultDuration evidence.

## Reproduction

With the isolated prefix and both captured inputs still present:

```sh
python3 -m unittest discover -s tools/media-qualification/ffv1 -p 'test_*.py' -v
python3 tools/media-qualification/ffv1/qualify.py \
  --output /tmp/deadpan-ffv1-normal.json \
  --work-dir /tmp/deadpan-ffv1-normal
python3 tools/media-qualification/ffv1/qualify.py \
  --sanitizers \
  --output /tmp/deadpan-ffv1-sanitizers.json \
  --work-dir /tmp/deadpan-ffv1-sanitizers
```

The final runs passed five Python parser tests, both strict C builds, three
pixel-exact cases per build, 21 rejecting controls per build, and three measured
last-byte decoder limitations per build. No GUI or model inference was run.
